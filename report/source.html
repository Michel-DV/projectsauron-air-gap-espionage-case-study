Executive Brief

1. Incident at a glance

ProjectSauron was a long-running Windows cyber-espionage platform publicly exposed in 2016 after years of activity. Kaspersky described operations dating back to at least June 2011; Symantec independently tracked the actor as Strider and the modular malware platform as Remsec.

Activity windowAt least 2011-2016 in public reporting.
Primary purposeLong-term intelligence collection and cyber-espionage.
PlatformsWindows x86 and x64 systems observed.
Initial accessPublicly unresolved.
Core architectureModified Lua runtime, encrypted VFS and task-specific plugins.
Signature capabilityCovert transfer across air-gapped networks using specially prepared USB media.
Core distinction: ProjectSauron should not be reduced to "USB malware." The public evidence describes a broad espionage architecture spanning authentication processes, memory-resident execution, internal relays, multiple network protocols, removable media and target-specific operational security.

Scope and confidence

Claim classTreatment in this report
ConfirmedVendor-observed behaviors such as password-filter persistence, modular plugins, DNS use, internal relays, removable-media tooling and victim-specific customization.
Strongly supportedProjectSauron/Strider was optimized for low-repeatability espionage rather than noisy mass deployment.
UnknownInitial infection vector, complete victim set, full operator structure and whether an undisclosed exploit was used in rare entry scenarios.
Case model: unresolved entry -> privileged Windows environment -> domain-controller persistence -> modular memory execution -> internal relays -> covert network exfiltration -> removable-media bridge -> air-gapped collection.

2. 2011-2016: years below the radar

Victims & Objectives

3. High-value targets and the intelligence objective

Public victim telemetry points to selective espionage against organizations central to state functions, strategic communications and sensitive infrastructure.

Kaspersky visibility

More than 30 infected organizations were reported across Russia, Iran, Rwanda and possibly Italian-speaking countries. Reported sectors included government, scientific research, military, telecommunications and finance.

Symantec visibility

Symantec reported evidence on 36 computers across seven organizations, including targets in Russia, an airline in China, an organization in Sweden and an embassy in Belgium.

Do not merge these datasets. They reflect different products, customers, collection windows and investigation scopes.

Focus on secure communications

Kaspersky reported strong interest in communication-encryption software used by government organizations. Collection included encryption keys, configuration files and network information associated with key-management or secure-communications infrastructure.

The strategic target was not merely a document. Authentication flows, encryption material and communication infrastructure can expose identities, relationships, message paths and future collection opportunities.

Critical-infrastructure nuance

Some affected organizations could be classified as critical infrastructure, but Kaspersky did not report ProjectSauron operating inside SCADA networks or targeting specific industrial control systems. The case is better understood as strategic espionage than as an ICS sabotage operation.

Platform Architecture

4. A platform, not a single implant

ProjectSauron combined loaders, backdoors, a modified Lua runtime, encrypted containers, virtual filesystems and specialized plugins. The important design choice was separation: persistence, orchestration and task-specific capability did not need to live in one stable binary.

Persistent footholdSmall stable component retains access in a privileged trust position.
Encrypted VFSConfiguration, scripts and plugin material remain packaged and concealed.
Lua orchestrationA modified runtime controls high-level task sequencing.
Plugin executionCollection, discovery, transport and exfiltration capability appears only when required.

Why modularity mattered

Kaspersky documented more than 50 plugin types. Symantec likewise described executable blobs and Lua modules delivered as a modular framework. A defender could recover one component and still fail to reconstruct the platform if the surrounding trust path and runtime state were ignored.

Disk view

Outer containers, loaders and persistent modules may be present, but not every operational capability has to exist as a durable file.

Runtime view

Decrypted configuration, loaded plugins, in-memory scripts and active network tasking can reveal far more than static filesystem triage.

Detection implication: architecture-oriented hunting asks which process owns the long-lived trust position, which modules appear only after tasking, where state is stored, which host becomes a relay and whether removable-media geometry contradicts the visible filesystem.
Analytical model: persistence is the anchor; orchestration is the control plane; plugins are disposable capability.

Authentication Abuse

5. Domain controllers as credential collection points

One of ProjectSauron's most strategically powerful techniques was persistence through the Windows authentication stack.

Trust conversion: legitimate authentication extension -> privileged code in a security-sensitive process -> plaintext credential visibility -> broader network leverage.

Password-filter persistence

Kaspersky reported that ProjectSauron could register a persistence module on domain controllers as a Windows LSA password filter. Password filters are legitimate mechanisms used to enforce password policies. The malicious module abused that trust position to observe credentials when users logged on or changed passwords.

Why it is high-value

  • Domain controllers naturally process privileged identities.
  • The operating system must handle password material before irreversible hashing.
  • Long-lived access can avoid repeated noisy credential-dumping operations.

Why it can be overlooked

  • Authentication extensions are expected to be privileged.
  • Security tooling may focus on database access rather than extension registration.
  • A stable module can blend into a long-lived server baseline.

Defensive choke point

Password-filter and Security Support Provider registration should be governed like domain-admin membership or production signing keys: rare changes, explicit ownership, allowlisted code, peer approval and immediate review when module inventory changes.

Hunting question: why is an unapproved DLL loaded into LSASS on a domain controller, and what administrative event caused it to appear?

Lua & Memory

6. Encrypted VFS and ephemeral capability

The combination of a modified Lua engine, encrypted virtual filesystem and memory-only modules gave operators a flexible control plane while reducing conventional file-based evidence.

LayerObserved role
StorageVFS encrypted with RC4 or Salsa20 depending on platform/version and compressed with zlib.
ExecutionPrecompiled Lua scripts controlled task flow through an embedded, modified runtime.
CustomizationThe embedded Lua interpreter was modified, including UTF-16 handling for strings and variable names.
Plugin modelDLL-like plugins exposed console-style behavior and could be chained by the orchestration layer.
1 · FootholdStable component retains access.
2 · TaskingOperator selects a capability only when needed.
3 · Memory loadPlugin appears in executable memory.
4 · DisappearCapability may vanish after reboot or task completion.

Forensic consequence

A clean disk is not proof of a clean host. Memory capture, loaded-module enumeration, executable-memory telemetry, handle inspection and network-to-process correlation may be the only way to reconstruct transient capability.

Forensic priority: when an encrypted container is present, acquisition of process memory can expose decrypted configuration, runtime state, task sequencing and plugins that the on-disk artifact intentionally conceals.

Internal Deployment

7. Trusted administration as an execution path

Kaspersky reported cases where ProjectSauron modules were deployed by modifying scripts that administrators already used to distribute legitimate software updates inside the target network.

Approved deployment script
Expected to execute across many hosts.
->
Injected command
Small downloader or new task embedded into trusted workflow.
Internal / external address
Payload retrieval follows an allowed administration path.
->
Broader execution
Centralized trust converts one compromise into fleet reach.

Why this is strategically effective

  • The deployment channel already has administrative reach.
  • Execution occurs under identities expected to install software.
  • Network routes to update servers are often pre-authorized.
  • Blue teams may suppress alerts from approved distribution systems.
  • Script changes can look like ordinary operations unless provenance is enforced.
  • One modified workflow can cross multiple segmentation boundaries.

Dormant listeners and internal relay nodes

ProjectSauron did not require every compromised server to communicate directly with the Internet. Some implants could remain dormant and wait for specific wake-up traffic. Where domain controllers lacked Internet access, other systems with both internal and external connectivity could function as relay nodes.

Behavioral invariant: even if the external infrastructure is unique to one victim, the role change of an internal server is observable. A web, proxy or update server should not suddenly relay opaque traffic between sensitive segments and the Internet.

Communications

8. Multi-protocol command, data and DNS signaling

ProjectSauron / Remsec supported several network mechanisms rather than depending on one conspicuous C2 protocol.

ChannelOperational valueDefensive angle
HTTP / HTTPSConventional web command and transfer.Process-to-destination correlation and proxy logs.
SMTPTransfer through email-like infrastructure.Unexpected SMTP clients and attachment behavior.
DNSMetadata exfiltration and operation-progress signaling.Rare domains, entropy, cadence and host role.
ICMPAlternate transport or wake-up behavior.Payload-bearing ICMP and unusual endpoint participation.
TCP / UDPCustom listeners and backdoor transports.Unexpected raw sockets, listeners and packet capture.
Named pipesLocal or internal command paths.Rare pipe names, unusual creators and cross-process access.

Low-bandwidth DNS tradecraft

Kaspersky documented a DNS exfiltration tool and a separate use of DNS for real-time operation-status reporting. Rather than bulk tunneling, the actor could encode small amounts of target metadata or signal operational milestones through target-specific subdomains.

Better than "detect DNS tunnels": track first-seen domains queried only by sensitive servers; high-entropy labels at low volume; query timing immediately after privileged configuration changes; and process-to-query relationships that contradict the server's historical role.
Original hypothesis: milestone signaling may be more detectable than bulk exfiltration because one unusual query immediately after a privileged change can carry more investigative meaning than thousands of generic requests.

Air-Gap Operations

9. The removable-media bridge

ProjectSauron's most distinctive capability was moving information between Internet-connected and isolated environments using specially prepared USB media.

Connected hostInteracts with prepared removable media and stages content.
USB deviceContains a normal visible partition plus reserved physical storage.
Air-gapped hostCollects or exchanges data through the hidden store.
Return pathMedia carries collected content back to a connected environment.

What the public evidence proves

Kaspersky documented a toolkit module designed for hidden data transfer and cases in which air-gapped networks were penetrated. The USB was formatted so that the normal partition did not consume the full physical device; reserved sectors remained available for a custom encrypted structure.

Important boundary: the hidden-storage mechanism explains covert data transfer. It does not prove how code first executed on an air-gapped host. Kaspersky explicitly noted that another mechanism would be required for initial control, and no zero-day was identified in the analyzed material.

Security implication

An air gap removes direct network connectivity; it does not remove trust in physical media, transfer procedures or human movement. In this model, the removable device becomes a transport layer that crosses the segmentation boundary by design.

Boundary shift: network isolation -> media trust -> human-carried transport -> hidden storage -> delayed exfiltration.

Shadow Filesystem

10. Hidden storage beyond the visible partition

Kaspersky's technical analysis of the MyTrampoline component describes direct inspection of the physical disk layout when removable media arrives. The module looked immediately after the first partition recognized by the operating system for a specific magic value identifying a custom shadow filesystem.

LocationPhysical sectors after the normal OS-visible partition.
RecognitionCustom magic value and private format rather than a Windows-recognized filesystem.
Logical designSeparate areas for data written out and data brought back in.
ProtectionCryptographic protection around stored / transferred content.

Why ordinary DLP can miss it

Endpoint controls often reason about mounted files, known device IDs and filesystem events. The same legitimate USB device can still expose additional addressable sectors that the normal OS never presents as files. Blocking unknown devices alone therefore does not solve the problem if already-trusted media is abused.

Detection invariant: physical capacity != visible partition geometry. If a removable disk reports more addressable storage than the mounted partition consumes, the gap is a forensic object worth examining.

MyTrampoline's two-way model

The shadow filesystem supported bidirectional movement: local staging content could be written into one hidden area, while content from the opposite side could be extracted later into local storage and removed from the media.

connected side -> hidden outbound area -> air-gapped side
air-gapped collection -> hidden return area -> connected side -> remote repository / C2

Forensic response

Acquire the entire block device, not only files copied from the mounted volume. Partition-table review, raw-sector inspection and entropy analysis can reveal hidden storage that normal filesystem triage completely omits.

Collection Mission

11. Credentials, documents and encryption infrastructure

ProjectSauron combined broad collection capability with a strategically focused interest in authentication and secure communications.

Credentials

Password-filter persistence created opportunities to capture plaintext credentials as authentication events occurred.

User activity

Remsec modules included keylogging and conventional file-stealing capability.

Encryption ecosystem

Kaspersky reported collection of encryption keys, configuration files and IP addresses related to custom network-encryption products used by government targets.

Removable media

Dedicated components collected documents from inserted USB storage.

Stealing a key or configuration file can be more valuable than stealing one document: it may unlock future communications, reveal trust relationships or expose the topology of secure messaging infrastructure.

Detection opportunities

  • Monitor unusual access to key stores and configuration directories.
  • Correlate removable-media insertion with bulk file reads.
  • Alert when authentication-sensitive processes access unrelated document or key material.
  • Preserve audit telemetry for administrative access to secure-communications systems.
  • Correlate credential collection with subsequent internal movement and new relay behavior.
Mission context matters: a single file-read event may be ordinary. Authentication data, secure-communications configuration and removable-media collection occurring within the same intrusion story is not.

Operational Security

12. Per-target customization and anti-forensics

ProjectSauron reduced the value of traditional IOC sharing by tailoring artifacts, infrastructure and metadata to individual victims.

LayerCustomization pattern
ImplantsUnique or heavily customized per target.
FilenamesMasqueraded as legitimate software or environment-appropriate components.
TimestampsTailored to the victim environment; tooling could copy timestamps from legitimate files.
C2 / infrastructureDomains and servers intended not to be reused across victim organizations.

The IOC paradox

A hash can be perfect for one infected organization and almost useless for the next. The stronger analytical objects are behavioral relationships: unusual password filters, raw removable-media access, internal relay roles, memory-only module loading, novel DNS patterns and administrative workflows that change without valid provenance.

Timestamp tailoring and cleanup

Public analysis documented tooling that could copy timestamps from legitimate files and tailor PE / filesystem metadata. Other components could remove files after collection or task completion.

Weak evidence alone

File creation time, PE timestamp and "old-looking" metadata can all be manipulated.

Stronger chronology

MFT/USN records, EDR first-seen time, backup history, peer-system comparison, signature/catalog state and deployment logs provide harder-to-fake context.

Original hypothesis: environment-perfect timestamps become suspicious when content provenance is absent. An old-looking file missing from golden images, manifests and peer systems deserves more scrutiny, not less.

Discovery & Hunting

13. How do you hunt malware designed to erase patterns?

The answer is to stop treating the indicator as the whole detection model. Both major investigations began with behavior that contradicted the expected role of trusted systems.

Weak standalone signalStronger correlated question
One suspicious hashWhy is an unapproved module loaded into LSASS on a domain controller?
One rare domainWhy does a high-value server query a new domain with recurring high-entropy labels?
One USB insertionDoes the physical media layout contain addressable sectors beyond the mounted partition?
One unsigned DLLWas it deployed through an administrator script that changed outside normal approval?
No file on diskDid the process allocate executable memory or receive a transient module immediately after network tasking?
Hunting principle: when the adversary attacks the indicator layer, shift detection toward invariants: privileged trust positions, role changes, memory execution, protocol misuse, removable-media geometry and unexpected data flow.

Telemetry priority

  • Domain-controller module inventory
  • Registry change auditing
  • EDR memory / module telemetry
  • MFT and USN chronology
  • DNS, proxy and flow logs
  • Removable-media raw-device metadata
  • Deployment-script version control
  • Centralized admin-system audit logs
Investigation mindset: reconstruct relationships between trusted components rather than waiting for the same malicious filename to appear twice.

Detection Engineering

15. Detection hypotheses and defensive blueprint

Historical IOCs are useful for retrospective hunting, but ProjectSauron's per-target customization makes control-oriented hypotheses more durable.

HypothesisTelemetryValidation
Unauthorized auth extensionRegistry, LSASS module inventory, code-signing metadata.Compare against approved domain-controller baseline and change tickets.
Memory-only taskingEDR executable memory, network-to-process correlation, module load events.Look for transient executable code with no durable provenance.
Deployment-script abuseGit/config history, script hashes, admin audit logs.Alert on unreviewed commands, raw IPs and new downloaders.
Internal relay role changeNetFlow, proxy, firewall and host network telemetry.Detect servers bridging segments or initiating novel egress.
Low-volume DNS signalingResolver logs, query entropy, first-seen domains.Correlate with privileged configuration changes.
Hidden removable-media storageDisk capacity, partition table and raw-sector acquisition.Compare visible partition end with physical storage size.
Timestamp cloningMFT, USN, EDR first-seen and software inventory.Trust event chronology over mutable file metadata.
Control blueprint: harden the trust positions first. Authentication-process integrity, governed software deployment, segmented egress, centralized DNS, memory-capable EDR and controlled removable-media transfer deliver more durable coverage than expanding a static hash blocklist.

Correlation beats isolated alerts

A rare DNS lookup, a USB insertion or a script edit may be benign alone. A privileged configuration change followed by unusual DNS, transient memory execution and a new internal relay role is an investigation-worthy sequence.

Design goal: preserve enough cross-layer telemetry that the operation can be reconstructed even when every individual binary, filename or domain is unique.

Research Notes & Evidence

16. Safe emulation, myths and primary sources

Safe Red Team / research emulation

Authorized labs can validate the same detection surfaces without recreating the espionage platform.

  • Register a benign test authentication extension in an isolated Windows lab and verify detection / approval workflows.
  • Use a harmless in-memory plugin that writes a marker instead of collecting credentials.
  • Modify a lab-only deployment script to launch a benign test binary and verify configuration-drift alerting.
  • Generate synthetic DNS labels containing non-sensitive test strings at low volume.
  • Create a removable-disk image with unused sectors after the visible partition and verify raw-device inspection.
  • Simulate an internal relay using approved test traffic and validate segmentation analytics.
Do not emulate: plaintext credential theft, covert exfiltration from third parties, unauthorized removable-media manipulation, persistence on production domain controllers or real-world air-gap intrusion.

Common myths

MythCorrection
"ProjectSauron was a USB worm."USB transfer was one specialized capability inside a broader modular espionage platform.
"The air-gap technique proves a zero-day."Public analysis did not identify a zero-day in the examined material.
